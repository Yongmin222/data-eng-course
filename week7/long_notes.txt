[수집] 수집은 원천에서 데이터를 가져오는 단계입니다. 크롤러는 웹 페이지를 읽어 필요한 값만 뽑고, CDC는 데이터베이스의 변경분만 골라 옮깁니다. 외부 API를 부를 때는 호출 한도를 지켜야 하고, 실패하면 잠시 쉬었다가 다시 시도합니다. 원천 시스템에 부담을 주지 않도록 한꺼번에 많이 가져오지 않는 것도 수집의 예절입니다.

[저장] 저장은 가져온 데이터를 오래 두는 단계입니다. 오브젝트 스토리지는 파일을 싸게 많이 둘 수 있어 원본 보관에 알맞습니다. Parquet 같은 열 형식은 필요한 열만 읽어 분석이 빠릅니다. Iceberg는 그 위에 테이블과 스냅샷을 얹어 이전 시점의 데이터를 다시 읽게 해 줍니다.

[처리] 처리는 데이터를 쓸모 있는 모양으로 바꾸는 단계입니다. 배치 처리는 정해진 시각에 모아서 한꺼번에 처리하고, 스트리밍 처리는 데이터가 생기는 즉시 흘려보내며 처리합니다. 어느 쪽을 쓸지는 늦게 알아도 되는 일인지 아닌지로 정합니다. 대용량 배치는 Spark로 여러 컴퓨터에 나눠 처리합니다.

[분석] 분석은 데이터에서 질문의 답을 찾는 단계입니다. SQL의 집계와 윈도 함수로 기간별 합계와 순위를 구합니다. 같은 질문을 자주 하면 결과를 미리 계산해 둔 요약 테이블을 만들어 둡니다. 분석가가 믿고 쓰려면 숫자의 정의가 문서로 남아 있어야 합니다.

[서빙] 서빙은 만든 결과를 사람이나 프로그램에 내주는 단계입니다. 대시보드는 사람이 보고, API는 다른 프로그램이 부릅니다. 자주 묻는 값은 캐시에 두어 매번 계산하지 않습니다. 응답이 느려지면 어느 단계에서 시간이 드는지 먼저 재 봅니다.

[운영] 운영은 파이프라인이 매일 제대로 돌게 지키는 일입니다. Airflow 같은 오케스트레이터가 작업 순서를 지키고, 실패한 작업은 정해진 횟수만큼 다시 시도합니다. 그래도 실패하면 담당자에게 알림을 보냅니다. 로그와 실행 기록을 남겨야 어제 무엇이 늦어졌는지 찾을 수 있습니다.

[품질] 품질은 데이터를 믿을 수 있게 지키는 일입니다. 결측치와 중복을 세고, 스키마가 바뀌지 않았는지 검사합니다. 검사에 걸린 행은 지우지 않고 격리 폴더로 옮겨 나중에 원인을 찾습니다. 품질 지표를 매일 기록하면 갑자기 나빠진 날을 바로 알아챕니다.

[보안] 보안은 데이터와 접근 권한을 지키는 일입니다. API 키와 비밀번호는 코드에 적지 않고 .env 같은 별도 파일이나 비밀 저장소에 둡니다. 사람과 프로그램에는 꼭 필요한 권한만 줍니다. 개인정보는 가리거나 지운 뒤에 분석용 저장소로 옮깁니다.
