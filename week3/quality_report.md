# 3주차 산출물 — 데이터 품질 리포트

## 1. 대상
- 원본: orders.csv (1,015행) — 3-1에서 생성, 시드 고정
- 정제 결과: orders_clean.parquet (1,000행)
- 파이프라인: clean_orders.py (DuckDB 추출 + Pandas 정제)

## 2. 품질 지표 전후 비교
| 지표 | before | after |
|---|---|---|
| 행 수 | 1,015 | 1,000 |
| order_id 중복 | 15 | 0 |
| price 결측 | 30 (2.96%) | 0 |
| category 고유값 | 5 | 4 |

## 3. 처리 내용과 근거
| 문제 | 처리 | 근거 |
|---|---|---|
| category 앞뒤 공백 20건 | str.strip() | ' 식품 '이 '식품'과 다른 값으로 집계돼 카테고리가 5가지로 세어짐 |
| order_date 타입 | to_datetime() | DuckDB 로 읽으면 이미 날짜지만, pd.read_csv 로 읽으면 문자열이라 같은 결과를 보장하려고 남김 |
| order_id 중복 15건 | drop_duplicates(keep='first') | 같은 주문이 두 번 세어져 매출이 부풀려짐 |
| price 결측 30건 | 중복 제거 뒤 중앙값으로 보정 | 결측률 2.96%로 낮음 · 이상치에 흔들리지 않는 중앙값 · 순서를 바꾸면 중앙값이 달라짐(100,500 vs 101,000) |

## 4. 고치지 않은 것
- 가격·수량의 상한 검사는 하지 않았습니다. 정제 후 describe()로 확인한 결과 price는 1,000~199,000, quantity는 1~5 범위로 이상치가 없었지만, validate()에는 상한 검사가 들어 있지 않습니다.
- 중복 주문은 첫 번째 행만 남겼고(keep='first'), 중복된 두 행의 내용이 서로 다른지는 비교하지 않았습니다.
- 미래 날짜 검사는 5단계 실습 코드에는 있었지만 최종 파이프라인의 validate()에는 넣지 않았습니다.

## 5. 검증
- 재실행 검증: 같은 원본으로 두 번 돌려 결과가 동일함을 확인 (equals() True)
- 교차 검증: DuckDB로 다시 측정해 Pandas 결과와 일치 확인
- 유효성 검사: 음수 가격·수량, 미지 카테고리 0건
- 검사기 자체 검증: 일부러 나쁜 값을 넣어 검사기가 잡는 것을 확인

## 6. 남은 과제
- 현재 데이터는 정상 범위지만, 원본이 바뀌어도 잡을 수 있도록 validate()에 가격·수량 상한 검사를 추가할 계획입니다.
- 결측 가격을 전체 중앙값 하나로 채웠습니다. 카테고리별 중앙값으로 채우는 방법과 결과를 비교해 보려 합니다.
- 미래 날짜 검사를 최종 파이프라인에 포함하고, 중복 행의 내용이 다른 경우를 따로 집계해 어느 행을 남길지 기준을 정하려 합니다.
